CPS Portal Help

How to use the machine questionnaire, commissioning workflow and customer sign-off.

Customer guide

The portal keeps the machine specification, machine testing and final acceptance together under one CPS project reference. You do not need to download or manage JSON files.

1

Sign in

Enter your email address and request a sign-in email. Enter the code from the email into the portal. No password is required.

The same email address can have more than one machine/project. Use the project selector to choose the correct CPS reference.

2

Stage 1 – Machine information

Complete the questionnaire for the machine, control, CAM system, machine capabilities, safe positions and required post functions.

  • Progress is saved automatically.
  • You can use Save now, sign out and return later.
  • If you require machine simulation, a machine CAD model is mandatory.
  • Please upload supporting manuals, proven NC code, machine-at-home photographs and rotary-zero photographs where requested.
Mobile / shop-floor use: the CPS portal is designed to work on phones and tablets as well as desktop computers. If the machine area has no usable internet connection, record the required information/photos and continue the portal when connected. If a site genuinely cannot use the online portal, contact Cam Post Solutions for an alternative arrangement.
3

Submit Stage 1

When the machine information is complete, submit the questionnaire to Cam Post Solutions for review. Submission starts the CPS review and quotation/scope process; it does not start machine testing.

What happens next: CPS reviews the submitted machine information, resolves any questions with you, agrees the technical/commercial scope, then develops the post processor and/or simulation. When a testable revision is ready, CPS publishes it in the portal and emails you. That release automatically opens its own Stage 2 commissioning run.
4

CPS development & test release

Once the specification is locked and the commercial scope is agreed, CPS develops the post processor and/or machine simulation. When a testable revision is ready, the files are published to your project portal with release notes. You can then download the exact revision intended for machine testing.

90-day support period: the CPS Terms define the Delivery Date as the date the first deliverables are made available for acceptance testing. The portal records that first release date and shows the 90-day support/modification window. Later revised releases do not restart the 90 days unless CPS agrees an extension in writing.
5

Stage 2 – Commissioning

Every released post/simulation revision gets its own numbered commissioning run. The checklist is generated from the Stage 1 machine configuration and is tied to the exact release being tested.

  • Record each test as Pass, Fail, Not tested or N/A.
  • Add notes for observed machine behaviour or changes made at the control.
  • Use controlled machine-testing practices and proven machine/manual information.
  • Upload the actual tested NC/results and the CAM test project. These are mandatory for a completed/retest result.
  • Once a commissioning run is submitted it becomes read-only, preserving what was actually tested.
6

Commissioning outcome

Select the outcome that reflects the test:

  • Ready for sign-off – the agreed functions are proven and there are no blocking issues.
  • Retest required – CPS will review the locked run and issue a revised release for a fresh commissioning run.
  • Blocked – CPS will review the locked run and resolve the missing information/dependency before a new release is issued.
7

Stage 3 – Customer acceptance

Once commissioning is complete, review the machine-test record and identify the exact post/simulation revision being accepted.

Choose Accepted, Accepted with limitations or Not accepted. A Not accepted result returns the project to commissioning for further work/retest.

Accepted records become the project baseline. Later post or simulation changes should use a new revision and, where appropriate, another commissioning/sign-off cycle.

If something goes wrong

  • If the sign-in code does not arrive, check junk/spam and make sure the email address is correct.
  • If a field or machine option looks wrong, stop and tell Cam Post Solutions rather than guessing safety-critical information.
  • If you cannot access Stage 2, it has probably not yet been enabled by CPS.
  • If a large machine model/CAM file cannot be uploaded, contact CPS for an alternative secure transfer method.

CPS internal staff guide

The internal dashboard controls the progression of projects from customer specification through machine verification to acceptance.

1

Open the CPS Project Dashboard

Sign in using an authorised CPS staff email. The dashboard shows all projects, not just projects owned by that email account.

2

Review Stage 1

Before locking the Stage 1 specification, check the questionnaire and evidence against the agreed project scope.

  • Machine / control / CAM details.
  • Kinematics, rotary directions/limits and machine configuration.
  • Safe retracts, tool-change positions and other safety-critical movement.
  • Relevant control features.
  • Required post functions.
  • Programming manuals and proven NC examples.
  • Machine CAD model where simulation is included.
  • Home/reference and rotary-zero photographs where relevant.
Do not enable commissioning if safety-critical information is still assumed or contradictory. Obtain confirmation from manuals, proven NC or the machine/customer first.
3

Request changes or lock the specification

If information is incomplete, use Request Stage 1 changes and state exactly what is needed. Once the information is agreed, use Lock specification. That becomes the development baseline.

4

Commercial agreement & development

After price/scope has been agreed, use Commercial agreed · Start development. The customer can see the project status but cannot alter the locked baseline.

5

Create and release a test revision

Create a draft test release, upload the post processor, simulation/test project and release notes as applicable, then use Release to customer. Draft release files remain private until released. Releasing the package opens Stage 2 commissioning and, when notifications are enabled, emails the customer a secure portal link.

For a timed trial, choose Protected trial / commissioning post. Select the provider and 7 / 14 / 30 / 60 day expiry (or a custom date). The uploaded source .cps remains CPS-internal. The release panel then shows the exact provider, support email, expiry date and Force Expired setting to enter into the CPS Post Expiry Tool. Generate the encrypted output locally, then upload the generated protected .cps to the draft. The portal blocks publication until every source post has a protected output. The Autodesk encryption password is never stored in the portal.

90-day support clock: the first released test version becomes the project Delivery Date and starts the 90-day support/modification period. Later v1.1/v2 releases do not reset it. If CPS agrees an extension in writing, record the extended date and agreement reference on Project Home.
5A

Customer correspondence & Project files

Portal emails use the CPS Support mailbox as the Reply-To address. If a customer replies with manuals, completed forms, NC files, CAM projects, photos or other evidence:

  • Keep the email in the CPS mailbox as the communication record.
  • Use the dedicated CPS job chat to pull the relevant email/attachments in for analysis where useful.
  • Save important attachments into Project files on Project Home and choose the appropriate category.
  • Use Source / reference to note the email/date or other origin, so the permanent project record is traceable.

Project files are CPS-internal and are not exposed to customers through the portal.

6

Commission the machine

The Stage 2 checklist is generated from Stage 1. Record observed behaviour rather than only whether the NC is syntactically valid.

  • Use Pass/Fail/Not tested/N/A consistently.
  • Record machine edits and post changes.
  • Flag safety-critical failures clearly.
  • Mandatory evidence is tested NC/results plus the actual CAM test project.
  • Keep limitations and anything not tested explicit.
7

Decide the Stage 2 outcome

Only use Ready for sign-off when the agreed scope has been adequately tested and blocking issues are resolved. Any submitted commissioning run is locked. For Retest required / Blocked, open the run as CPS staff, record the review, upload the revised post/simulation and use Release revised version to customer. That creates the next numbered commissioning run without overwriting the previous evidence.

8

Stage 3 acceptance

Stage 3 identifies the exact final post/simulation revision, known limitations, customer representative and acceptance result.

Accepted and Accepted with limitations lock the release baseline. Not accepted returns the project to Stage 2 as Retest required.

9

After acceptance

Use the accepted record as the baseline for future support. Accepted or Accepted with limitations automatically moves the project from the active CPS dashboard into the collapsed Archived projects section. Archiving does not remove any releases, evidence, Project files or sign-off history, and the 90-day support period still runs from the original Delivery Date, not from acceptance or a later revision.

If further work is genuinely required, CPS staff can use Reopen project to return it to the active dashboard without changing the accepted baseline.

Storage: customer/project records and uploads are stored in the private CPS Supabase project store. GitHub should contain the portal/web code only, not customer machine data.

Internal good practice

  • Use the portal/dashboard to change stage status rather than manually editing database rows.
  • Do not overwrite an accepted baseline to represent a later revision.
  • Keep customer actions separate from CPS actions in commissioning notes.
  • Do not mark untested functionality as proven.
  • Where a machine condition cannot be verified safely, record it as Not tested / Blocked and obtain the required evidence.

Testing / support note

Use the CPS project home page as the normal entry point. If a page does not behave as expected, record the CPS project reference and contact CPS Support.
